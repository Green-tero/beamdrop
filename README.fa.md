# بیم‌دراپ (BeamDrop)

[English](README.md) · [فارسی](README.fa.md)

یک ابزار بی‌دردسر، سبک و سریع برای انتقال فایل و متن به صورت همتا‌به‌همتا (P2P) در بستر شبکه محلی و مستقیماً داخل مرورگر. بدون نیاز به ایجاد حساب کاربری، بدون آپلود در سرورهای ابری و بدون نیاز به نصب هرگونه نرم‌افزار جانبی.

این پروژه از پروتکل WebRTC برای انتقال مستقیم اطلاعات بین دو دستگاه و از یک سرور سیگنالینگ ساده با WebSocket برای پیدا کردن خودکار دستگاه‌های موجود در یک شبکه استفاده می‌کند.

---

## چرا این پروژه رو ساختم؟

من هر روز بین لینوکس، ویندوز، مک و گوشی اندرویدی جابه‌جا می‌شم. قابلیت‌هایی مثل AirDrop تا زمانی که کاملاً درون اکوسیستم اپل باشید فوق‌العاده هستن؛ اما به محض اینکه بخواید یک اسکرین‌ریکورد ۲ گیگابایتی رو از سیستم ویندوزی به آیپد بفرستید یا فایل لاگ رو از سرور لینوکس به گوشی اندروید منتقل کنید، راه‌حل‌ها آزاردهنده می‌شن:

- پیام‌رسان‌ها حجم فایل رو محدود یا کیفیت ویدیو رو کم می‌کنن.
- فضاهای ابری مثل گوگل درایو یا دراپ‌باکس بی‌دلیل حجم اینترنت شما رو مصرف می‌کنن، چون اول باید فایل رو آپلود کنید و بعد روی دستگاهی که نیم متر اون‌طرف‌تر روی میزه دانلودش کنید!
- اشتراک‌گذاری‌های محلی مثل Samba دردسرهای تنظیمات و عدم دسترسی در شبکه‌های Guest رو دارن.

بیم‌دراپ حاصل این نیاز شخصی بود. کافیه صفحه رو روی دو دستگاه متصل به یک وای‌فای باز کنید، فایل رو بکشید و رها کنید؛ داده‌ها با بالاترین سرعتی که روتر وای‌فای شما پشتیبانی می‌کنه، مستقیماً بین دو مرورگر جابه‌جا می‌شن.

---

## امکانات کلیدی

- **انتقال مستقیم همتا‌به‌همتا (P2P):** فایل‌ها و متن‌ها مستقیماً از طریق DataChannelهای رمزنگاری‌شده در WebRTC منتقل می‌شن.
- **بدون ذخیره حتی یک بایت در سرور:** سرور واسط تنها وظیفه دست‌تکانی اولیه (Signaling) رو به عهده داره و هیچ اطلاعی از محتوای فایل شما نداره.
- **تکه‌بندی ۶۴ کیلوبایتی همراه با کنترل فشار بافر (Backpressure):** برای فایل‌های حجیم (حتی چند گیگابایت)، داده‌ها به قطعات ۶۴ کیلوبایتی خرد می‌شن و با مانیتور کردن بافر مرورگر (`bufferedAmountLowThreshold`) از کرش کردن تب جلوگیری می‌شه.
- **شناسایی خودکار بر اساس شبکه و آی‌پی:** تمام دستگاه‌های حاضر در یک شبکه وای‌فای یا ساب‌نت به طور خودکار در یک اتاق قرار می‌گیرن.
- **رابط کاربری دوزبانه (فارسی و انگلیسی):** پشتیبانی کامل از چینش راست‌به‌چپ (RTL)، تایپوگرافی مناسب و ذخیره زبان انتخابی در حافظه مرورگر.
- **اشتراک‌گذاری فوری متن و کلیپ‌بورد:** پنجره مخصوص ارسال متن، کد یا لینک با دکمه کپی فوری با یک کلیک.
- **صدای آرام اعلان:** استفاده از Web Audio API بومی مرورگر برای پخش ملودی ملایم هنگام اتمام انتقال فایل یا دریافت متن (بدون نیاز به فایل‌های صوتی سنگین).

## نحوه کار در پشت صحنه

### ۱. کشف دستگاه‌ها و سیگنالینگ (WebSockets)
```
[ دستگاه اول ]                                   [ دستگاه دوم ]
     │                                                │
     ├─── اتصال با WebSocket ─► [ سرور واسط  ] ◄──────┤
     │    (بررسی هش آی‌پی)      [ سیگنالینگ  ]         │
     │                                                │
     ├─── پیشنهاد اتصال (Offer) ─► ارسال به مقصد ────►│
     │◄── پاسخ اتصال (Answer) ◄─── ارسال به مبدا ─────┤
     │                                                │
     ├─── بسته‌های ICE Candidate ─► ارسال به مقصد ───►│
     │                                                │
     ▼                                                ▼
     ════════════ ارتباط مستقیم و رمزگذاری‌شده ═════════
                 (انتقال فایل / پیام‌های متنی)
```

۱. هر مرورگر به سرور سیگنالینگ WebSocket متصل می‌شه.
۲. سرور آی‌پی درخواست‌دهنده رو هش می‌کنه و دستگاه‌های دارای آی‌پی مشترک رو در یک اتاق مجازی قرار می‌ده (در محیط توسعه لوکال، آدرس‌های Loopback در اتاق مشترک قرار می‌گیرن تا بتوان با دو تب مختلف تست کرد).
۳. سرور یک نام مستعار تصادفی و بامزه (مثل *Cobalt Lynx* یا *Amber Fox*) اختصاص میده و نوع دستگاه رو مشخص می‌کنه.
۴. دستگاه‌ها بعد از تبادل مشخصات ارتباطی (SDP و ICE Candidates)، یک کانال مستقیم DataChannel ایجاد می‌کنن و از اون لحظه ارتباط کاملاً P2P و بدون حضور سرور خواهد بود.

### ۲. تکه‌بندی داده‌ها و چالش سرریز بافر (Backpressure)
کانال داده در WebRTC بر پایه پروتکل SCTP بنا شده. اگر بخواید یک فایل ۵۰۰ مگابایتی رو مستقیماً با متد `dataChannel.send()` ارسال کنید، مرورگر سعی می‌کنه کل فایل رو یک‌جا به صف بافر بفرسته و بلافاصله کرش می‌کنه.

برای حل این مشکل:
1. فایل‌ها به قطعات ۶۴ کیلوبایتی (`65,536` بایت) تقسیم می‌شن که بهترین تطابق رو با محدودیت‌های پکت SCTP داره.
2. بافر ارسال لحظه‌به‌لحظه بررسی می‌شه؛ اگر حجم در صف از ۵۱۲ کیلوبایت بیشتر شد، حلقه ارسال مکث می‌کنه تا رویداد `bufferedamountlow` مرورگر شلیک بشه و فضای بافر خالی بشه.
3. سمت گیرنده قطعات ورودی در حافظه جمع‌آوری می‌شن، نوار پیشرفت و سرعت لحظه‌ای محاسبه می‌شه و در پایان به صورت خودکار فایل دانلود می‌شه.

## تکنولوژی‌های استفاده‌شده

- **بک‌اند:** Node.js، Express، کتابخانه سبک `ws` (بدون اضافه‌باری Socket.io) و تایپ‌اسکریپت.
- **فرانت‌اند:** React 18، Vite، TypeScript، Tailwind CSS و آیکون‌های Lucide.
- **سازگاری نسخه‌های نود:** سازگار و تست‌شده روی Node.js نسخه **v20.x**، **v22.x** و نسخه جدید **v26.x**.
- **مرورگرها:** تمام نسخه‌های مدرن کروم، فایرفاکس، سافاری (آیفون، مک، آیپد) و اج.

## راه‌اندازی و اجرای محلی

### پیش‌نیازها
- نصب بودن Node.js (نسخه ۲۰ یا بالاتر تا نسخه ۲۶)
- ابزار npm نسخه ۹ به بالا

### ۱. دریافت پروژه و نصب وابستگی‌ها
```bash
git clone https://github.com/Green-tero/beamdrop.git
cd beamdrop
npm install
```

### ۲. اجرای پروژه در حالت توسعه

دو ترمینال مجزا باز کنید:

**ترمینال اول (سرور سیگنالینگ):**
```bash
cd server
npm run dev
```
سرور روی آدرس `http://localhost:3000` آماده به کار خواهد شد.

**ترمینال دوم (رابط کاربری فرانت‌اند):**
```bash
cd client
npm run dev
```
محیط Vite روی آدرس `http://localhost:5173` اجرا می‌شه.

حالا `http://localhost:5173` رو در دو تب مختلف مرورگر باز کنید تا همدیگه رو شناسایی کنن.

---

## اجرا با داکر (Docker)

پروژه دارای یک فایل `Dockerfile` چندمرحله‌ای سبک (Multi-stage بر پایه Alpine) هست که فرانت و بک‌اند رو داخل یک کانتینر واحد اجرا می‌کنه:

```bash
docker compose up -d --build
```
سپس از طریق مرورگر به آدرس `http://localhost:3000` مراجعه کنید.
